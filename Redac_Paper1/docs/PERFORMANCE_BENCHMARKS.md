## 🧠 Memory Scaling (OOM Protection)

The `260512` framework implements a **Memory-Aware Job Scheduler** to prevent hardware crashes. Memory is estimated using the formula:
$$M \approx N_{\text{sites}} \times (L + K + \text{SBD}) \times N_{\text{traj}} \times N_{\text{steps}} \times \xi$$
where $\xi$ is the `modes_factor` (9.0 for 189-mode FMO).

## 🛠️ Optimization Tips

1. **For Laptop Verification**:
   - Use the dedicated suite: `pytest tests/ -v -k "minimal"`
   - Reduce parameters in `laptop_parameters.yaml`: $L=2, K=1, n_{\text{traj}}=10, t_{\text{max}}=10\text{ fs}$.
2. **For Production Ensembles**:
   - Always use the `--parallel` flag on \qty{128}{GB}+ systems.
   - Use `--skip-audit` if hierarchy convergence has already been verified for the current Hamiltonian.
3. **Log Monitoring**:
   - Use `tail -f reproducibility/logs/execution_*.log` to monitor real-time memory pressure and thread gating.
